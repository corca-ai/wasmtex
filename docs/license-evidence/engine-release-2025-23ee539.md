# TeX Live 2025 engine release-candidate build evidence

This record covers the fresh engine artifacts built from WasmTex commit
`23ee539b04f41b53e5bed715fbb077e14e46ec24` and TeX Live source commit
`143f1723353b20202645f241db429b080a8adcdf`.

The WebAssembly compilation ran on an x86_64 Linux Docker builder. All five Docker
build paths used the Emscripten 3.1.46 image pinned by digest in
`scripts/corresponding-source-2025.json`. Format dumps were then generated by the
fresh pdfTeX, XeTeX, and LuaHBTeX artifacts. The XeTeX and LuaHBTeX dumps were
compressed with `gzip -n -9` so the gzip header carries no filename or timestamp.

## Link evidence

[`link-inventory-23ee539.json`](link-inventory-23ee539.json) records the SHA-256 of
seven linker maps and the static archives and direct objects selected for pdfTeX,
BibTeX, BibTeX8, makeindex, XeTeX, dvipdfmx, and LuaHBTeX. The inventory is bound
to the build IDs above and the single WasmTex source revision.

The link maps, generated JavaScript, and WebAssembly bytes passed aggregate scans
for `libpplib`, `pplib.a`, the `ppdoc_`/`ppdict_`/`pparray_`/`ppstream_`/`ppref_`
families, `utilsha`, and the removed legacy SHA digest helpers. No production
runtime switch or fallback to `pplib` was found.

## Runtime checks

- Every WASM file passed `WebAssembly.validate`.
- Every generated module exposed its required engine entry points.
- The freshly staged pdfLaTeX, BibTeX, makeindex, XeLaTeX, and LuaLaTeX artifacts
  passed their existing browser golden-output tests.
- The WTPDF native and WebAssembly smoke tests and the XeTeX geometry and visual
  fixture checks ran as part of the source builds.

This evidence clears only the fresh-artifact build gate. The candidate remains
non-releasable until the linked-component notices and LGPL relink materials,
compatibility/security gates, corresponding-source archive, and public-repository
audit are complete.
