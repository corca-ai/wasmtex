# TeX Live 2025 engine release-candidate build evidence (`2b58db3`)

This record covers the engine artifacts rebuilt from WasmTex commit
`2b58db337f9917925988dc51fbebd9e457f76128` and TeX Live source commit
`143f1723353b20202645f241db429b080a8adcdf`. It supersedes the mixed-revision
candidate recorded in
[`engine-release-2025-23ee539.md`](engine-release-2025-23ee539.md): the D-stage
repeat-image fixture found two WTPDF defects (an uninitialized file-document
`memstream` pointer freed on close, and a null-kind value returned for an
absent `/Info`), fixed in commit `8e5d27b`, which changed the LuaHBTeX and
XeTeX engine bytes.

The WebAssembly compilation ran on an x86_64 Linux Docker builder. All five
Docker build paths used the Emscripten 3.1.46 image pinned by digest in
`scripts/corresponding-source-2025.json`. The XeLaTeX and LuaLaTeX format
dumps were regenerated by the fresh XeTeX and LuaHBTeX artifacts and
compressed with `gzip -n -9`; their observed inputs are recorded in
[`format-inputs-xetex-2b58db3.json`](format-inputs-xetex-2b58db3.json) and
[`format-inputs-luahbtex-2b58db3.json`](format-inputs-luahbtex-2b58db3.json)
(the LuaLaTeX fetch set is identical to the `23ee539` record; the dump differs
by the known non-deterministic bytes). The pdfTeX engine and format bytes are
unchanged from the `23ee539` build, so
[`format-inputs-pdftex-23ee539.json`](format-inputs-pdftex-23ee539.json)
remains the accurate dump record for the identical staged bytes.

## Reproducibility

Rebuilding the four families whose sources did not change produced
byte-identical artifacts: `wasmtex-pdftex.{js,wasm,worker.js}`,
`wasmtex-pdftex.fmt`, `wasmtex-kpse-resolve.js`, `wasmtex-bibtex.*`,
`wasmtex-bibtex8.*`, `wasmtex-makeindex.*`, and `wasmtex-dvipdfm.*` all hash
equal to the `23ee539`-era staging. Only `wasmtex-xetex.wasm` and the
LuaHBTeX artifacts changed, matching the scope of the `8e5d27b` fix exactly.

## Link evidence

[`link-inventory-2b58db3.json`](link-inventory-2b58db3.json) records the
SHA-256 of seven linker maps and the static archives and direct objects
selected for pdfTeX, BibTeX, BibTeX8, makeindex, XeTeX, dvipdfmx, and
LuaHBTeX, bound to the build IDs above. The engine component inventory checker
passed against it (81 linked archives, 20 components, 7 executable families),
and the SPDX SBOM was regenerated as
[`engine-sbom-2025-2b58db3.spdx.json`](engine-sbom-2025-2b58db3.spdx.json).

The from-source builds re-ran their gates: the SHA-2 and WTPDF native and
WebAssembly smoke tests (now asserting the absent-`/Info` contract), the XeTeX
geometry and visual fixture checks, the new LuaHBTeX repeat-image lifetime
gate (five iterations), and the map/byte scans for `libpplib`, the
`ppdoc_`/`ppdict_`/`pparray_`/`ppstream_`/`ppref_` families, `utilsha`, and
the legacy SHA digest helpers — all clean.

## Runtime checks

- The freshly staged pdfLaTeX, BibTeX, makeindex, XeLaTeX, and LuaLaTeX
  artifacts passed all seven browser golden-output tests, including both
  PDF-import package corpora (`graphicx` + `pdfpages` + TikZ).
- The XeLaTeX PDF-import golden runs for the first time: commit `2b58db3`
  fixed the SDK to mirror project files into the dvipdfmx worker.
- Compatibility differentials against the non-distributed pplib baselines are
  recorded in
  [`luahbtex-pdfe-differential-923b196.md`](luahbtex-pdfe-differential-923b196.md)
  and
  [`xetex-pdf-extended-differential-2d87107.md`](xetex-pdf-extended-differential-2d87107.md).

This evidence refreshes the fresh-artifact and third-party-notices gates for
the new bytes. The candidate remains non-releasable until the remaining
compatibility/security items, the corresponding-source archive, and the
public-repository audit are complete.
